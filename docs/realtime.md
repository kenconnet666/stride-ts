# 全实时的技术路线（方案稿，2026-11-24）

用户 2026-11-24 定的方向，原话：

- "使用全光栅加缓存路线，仔细考虑一下路线"
- "编辑器和游戏始终是全实时的，改了马上看到是核心目标，其他阻碍的技术路线项目都修改，例如烘焙"
- "除了光追和烘焙，其他影响编辑器和游戏全程实时，改动即时可见的都尽量删除或者修改，而且新的技术路线应该性能更好，目标跑满我的这个4k120hz屏幕"
- "按照方案开始，遇到困难可以改方案……并且渲染的东西矢量和清晰"
- "除了光追，其他影响实时渲染，修改立即得到热重载反馈查看，从0开始能快速把世界展示出来的其他各种问题都要适当修改"

起因：软件光追在浏览器里没有硬件支持，每个像素只打得起一条射线，软阴影、面光源、多灯都是噪点，靠时间和空间降噪抹平，画面糊、反应慢（降噪的偏差还出过"黑雾"），也贵（4K 下超市一帧 40 毫秒，其中光追反射 11 毫秒）。

这份是方案稿：先讲原则和预算，再按系统列"留、删、改"，最后是分步的顺序和每步的验收。用户确认后进路线图，做的过程和数字记进 progress-log。

## 一、原则

1. **改了下一帧就对**：编辑器和游戏里的任何改动（挪物体、改材质、改灯、改生成参数、改天气时间）下一帧画面就是对的。不允许"等烘焙""等收敛""等编译"。
   - 允许的例外只有两种：
     - 物理上本来就慢的过程，比如自动曝光的适应，编辑器里可以关掉。
     - 一帧之内做不完的大量重算，要分几帧做完。分帧时先显示近似的结果（不是旧的、不是空的），并且有上限（几帧之内）。
2. **确定性的着色，不靠降噪**：每个像素的结果不是随机抽样再平均出来的。软阴影用确定的滤波，间接光用探针（探针层面平均，不在像素上出噪点）。时间上的累积只用于抗锯齿这类亚像素的东西，并且不能让改动拖影。
3. **没变就不做**：贵的结果（阴影图、探针、反射探针、生成的几何）缓存着，按"谁变了、影响到哪"精确地失效、只重算受影响的那部分。这是性能的主要来源，也是"改了马上看到"的保证：失效是即时的，重算的量很小。
4. **帧率目标 4K 120 Hz**：在这台机器（RX 9070 GRE、4K 120 Hz 的屏）上原生 4K，CPU 和 GPU 每帧都在 8.33 毫秒以内（p99 和最慢的帧）。代替 11-24 早些时候定的 4K 30 Hz。不靠降分辨率（11-19 的原则照旧：上采样只是玩家的选项）。
5. **导出成片和视口一样**：出片用同一个实时渲染器，只是可以超采样（多个子帧平均做抗锯齿、运动模糊）。看到的就是导出的，不再有另一套离线的光照。

## 三、按系统：留、删、改

### 直接光的阴影：缓存的阴影图（改）

现状：Stride 的做法，阴影图集每帧清空、重排、所有投阴影的光全部重画；面光源的阴影只有光追那一路。

改成：
- **持久的图集**：每盏光一块固定的地方，大小按它在画面上盖住多大分几档。档位有迟滞，变档时才重新分配，也只重画这一盏。
  - 用不上的光（离得远、看不见）不占地方。
  - 图集按显存预算有上限，满了按"盖住的大小 × 亮度"挑。
- **两层**：
  - 静态层：不动的投影者，失效时才画。
  - 动态层：每帧把静态层用写深度的全屏一遍拷过去（不依赖深度贴图的局部拷贝），再画这一帧动的投影者，只做那些照到动的东西的光。
  - 参考：Godot 4 的阴影图集按"几何和光相交、几何变了就让那盏光变脏"重画，每帧有重画上限；虚幻的静态加动态分层缓存。我们两样都用。
- **失效**：变换的变化来自原生变换存储的 `changedSlots()`，加上模型、材质换了、光本身改了。拿变了的东西的包围盒和光的影响范围（球、锥）比，相交的光失效。编辑器里挪一个货架，下一帧就只重画照到它的那几盏灯。
- **面光源**：
  - 矩形、圆盘朝一侧照，用一个宽视角的透视图，或者立方体去掉背面的五个面；管状的用六个面。
  - 半影用 PCSS：先在光源大小投到图上的范围里找挡光的平均深度，再按"光源大小 ×（接收距离 − 挡光距离）/ 挡光距离"定滤波的宽度。光源的长和宽分别投，长条灯管沿管子的方向滤得宽。
  - 采样是固定的图案加硬件比较的双线性，不随帧抖动，所以没有噪点、不用降噪。
  - 全亮、全暗的像素在找挡光那一步就提前结束，只有半影里的像素做完整的滤波（开销的大头在这里，要实测）。
  - 很长的灯管单点投影不准时，再考虑沿管子放两三张图。
- **太阳**：
  - 先做缓存的级联：每级按纹素对齐世界网格，相机挪不出一格就不重画静态层，挪出去时只画新露出来的一条。
  - 开放世界接着做虚拟阴影贴图（照 UE5）：每级是很大的虚拟图，按页分配物理页池（不需要稀疏纹理）。按这一帧深度缓冲里用到的页才分配、才画，页缓存到失效。每页画的时候用 `clip-distances` 裁到自己的页里。
- **接触阴影**（屏幕空间，已有，默认关）：管阴影图分辨率以下的小缝。

### 删掉的实时光追

| 删 | 现在用在哪 | 换成 |
|---|---|---|
| `RayTracedShadows`（方向光的光追阴影） | 站台 | 缓存的级联（以后虚拟阴影贴图）+ PCSS + 接触阴影 |
| `RayTracedLocalLights`（ReSTIR 多灯阴影） | 超市 | 缓存的面光源阴影 + PCSS |
| `RayTracedEmissive`（自发光的面当光源） | ScreenRoom | 发光的面由生成器带出解析的面光源（灯箱、屏幕给一盏矩形光）；弱的发光只进 DDGI 探针 |
| `RayTracedReflections`（光追补反射） | 超市、站台 | 屏幕空间反射，加盒子反射探针兜底（自动重拍，见下），加平面反射 |
| `ScreenDenoiser` | 上面三路共用 | 不需要 |
| `PathTracedLighting`（路径追踪的间接光） | 出片的选项 | 出片用实时的渲染器（原则 5） |
| 合成器的 `rayTracedShadows`、`emissiveLighting`，材质的 `emissiveLighting`，调试命令 `rtshadow`、`emissive`、`pathtrace` | | 删，场景文件里的字段由加载时的迁移去掉 |

**留下光追的 BVH**（`RayTracingScene`、`SurfaceColors`）给 DDGI 的探针用。探针的射线数很少（每帧几十万条，不是每像素），结果在探针上平均，不在像素上出噪点，也按预算调射线数。`RayTracedLighting`（打到的表面怎么受光）跟着探针留下，只留探针要的部分。

### 间接光：DDGI 探针（留，改响应）

- 已有：探针每帧光追、八面体的辐照度和距离图、跟着相机。
- 改：改动的包围盒里的探针立刻按"新探针"处理，头几次按平均混、不带迟滞，几帧之内收敛，不再等一秒左右的迟滞。
- 室内按房间、区域放更密的探针体（0.25～0.5 米），细的阴影交给 GTAO。
- 屏幕空间全局光照（已有，默认关）：要是它是抽样加时间累积的，就删。

### 反射（改）

- 屏幕空间反射留下，几步合并（路线图上已经记着的无损的那一项）。
- 反射探针现在只在加进来、挪了、改设置、太阳变了时重拍。
  - 改成盒子里的东西、灯变了也失效。
  - 编辑器里失效时同一帧拍完六个面（不再每帧一个面）；游戏里照旧分帧。
  - 上限从 16 个往上提。
  - 编辑器加"按房间自动放探针"。
- 平面反射留下（地面、水面）。

### 抗锯齿和清晰度（改）

- 先查 TAA 为什么在 4K 下要 13 毫秒（正常应该在 1 毫秒以内）。
- 比两条路，按三张照片和货架上的字比清晰度、量开销，选一条：
  - 4 倍 MSAA：前向渲染天然合适。加上镜面反射的抗锯齿（按法线的变化加粗糙度，Kaplanyan、Tokuyoshi 的做法），透明裁剪用 alpha-to-coverage；屏幕空间的那几遍要先解析出深度、法线。
  - 改好的 TAA：只抗亚像素的锯齿。物体动了、改了的地方不拖影，贴图的 mip 不跟着变糊。
- 细线（吊杆、电线、栏杆）：在顶点着色器里加粗到至少一个像素，按真实粗细的比例淡出（Humus 的 phone-wire AA）。
- 货架上中距离的字：位图换矢量按短边判断、换得更早一点，量矢量的开销。

### "改了马上看到"、"从零很快看到世界"的其他阻碍（审一遍，能删就删、能改就改）

从零开始（打开工程、开页面、加载场景）到画出第一帧也要快：要量开发服务器起来、编辑器后端打开工程（补烘生成的资源）、页面下载、原生模块初始化、着色器编译、场景加载各要多久，慢的同样按下表的办法改（先显示近似的，后台补齐）。

| 阻碍 | 现在 | 改成 |
|---|---|---|
| 管线没编好的批先不画（`deferPipelines`） | 新材质、新组合第一次出现时晚几帧才出来 | 着色器变体收拢成少数几个通用的（分支代替变体），常见的在启动时就编好；改材质不产生新管线 |
| 后端生成模型（货架、堆放、杂物、建筑、城市、树、白盒、SDF、多边形、文字、样条、碎块） | 存文件 → 后端生成 → 页面热重载，大的要几秒 | 先量每种从改参数到画面变的延迟。慢的挪到页面里（工作线程 + 原生 wasm）当场生成、马上显示，后端只负责存盘。堆放、菜落定这类物理过程在视口里实时跑出来，不在后台算完 |
| 导入时压缩贴图（KTX2） | 压完才用 | 先用原图显示，压缩在后台做完再换 |
| 远处卡片（impostor）的图集 | 运行时烘一次 | 模型变了自动重烘（分帧，期间画模型本身） |
| DDGI、反射探针的收敛 | 一秒左右的迟滞、每帧拍一个面 | 见上：改动处立刻重置、编辑器里一帧拍完 |
| 时间上累积的效果（体积雾、体积云、屏幕空间反射的时间累积） | 改动有拖影 | 查每一个：改动处丢弃历史；能确定性算的不累积 |
| 自动曝光的适应 | 编辑器里改灯以后亮度慢慢变 | 编辑器里默认立即（游戏里照旧适应） |
| 出片的路径追踪 | 和视口看到的不一样 | 删，出片用实时渲染器（原则 5） |

## 四、不透明着色从 8.5 降到 3.5 毫秒：要量了才知道的部分

这一项最没把握，先量清楚每部分的开销再动手。候选：

1. **灯的影响范围收紧、按贡献剔除**：超市的灯 `range: 9`，每个像素叠十几盏，大多数贡献很小。按"这盏灯在这里最多能贡献多少"确定性地剔除（低于可见的阈值就不算），不是随机挑。
2. **面光源的 LTC 简化**：远处的灯已经按小光源算。再看漫反射、镜面能不能共用更多。
3. **着色器收拢**：变体少了，寄存器压力、分支的开销要一起量。
4. **矢量贴图只在近处算**：量它在 4K 下占多少。
5. **静态表面的漫反射光照缓存**（最后的手段，量完前几项还不够时再做）：静态的灯照静态的表面，漫反射不随视角变。可以在表面的纹理空间里实时算一次、存起来，灯或物体变了只重算受影响的那块（运行时的光照缓存，不是离线烘焙，改了下一帧就对）；镜面每帧照算。要所有几何有不重叠的展开（生成器直接给，导入的模型用原生的 xatlas 展开）。工作量大，先不排。
